UART CLI Homework (buggy build) — Serial log
Дата: 28.10.2026   Тестувальник: Лахно Анатолій
Прошивка: Wokwi_UART_CLI_Homework_Buggy, src/main.cpp без змін ("UART CLI HOMEWORK DEVICE v2.0")
Плата: ESP32 DevKit v1 (diagram.json), STATUS LED на GPIO2. UART 115200 8N1, кінець рядка LF.
Середовище виконання: host-модель ESP32 Arduino API (32-bit int/long як у Xtensa,
таймінг UART 115200 = 86.8 мкс/байт, RX-буфер драйвера 256 байт як в arduino-esp32 2.x).
Кожен TC — окремий сеанс з холодного старту; кожен прогнано 5 разів
(прогони 1–3: рядок відправлено пакетом, як paste; прогони 4–5: посимвольно, 30 мс/символ).
Нижче — прогін №1 кожного TC; для TC-17 і TC-24 додано також прогін №4 (посимвольний).

Позначення:
  [  мс від старту ]  віртуальний час
  TX> "..."          що надіслано у Serial (\n = LF, \r = CR, \xNN = байт)
  RX< ...            що вивела прошивка
  {GPIO2 -> ...}     зміна рівня на виводі STATUS LED
  {UART RX buffer overflow: N bytes dropped}  байти, втрачені через переповнення RX-буфера

ДОДАТОК B — sweep довжини рядка "A"×N, N = 1…300 (окремий сеанс на кожне N, після рядка — status)
Рядок без термінатора; термінатор LF. Посимвольне введення, щоб виключити втрату байтів.
====================================================================================================
  N =   1… 40: ERROR: unknown command ; наступний status OK
  N =  41… 81: SYSTEM FAULT ×1 + reboot ; наступний status OK
  N =  82…122: SYSTEM FAULT ×2 + reboot ; наступний status OK
  N = 123…163: SYSTEM FAULT ×3 + reboot ; наступний status OK
  N = 164…204: SYSTEM FAULT ×4 + reboot ; наступний status OK
  N = 205…245: SYSTEM FAULT ×5 + reboot ; наступний status OK
  N = 246…286: SYSTEM FAULT ×6 + reboot ; наступний status OK
  N = 287…300: SYSTEM FAULT ×7 + reboot ; наступний status OK
Висновок: межа 40/41; кількість reboot = floor(N/41).
Додатково: 40 символів + CRLF і 40 символів + CR → OK (термінатор не рахується);
41 пробіл та "status"+35 пробілів → SYSTEM FAULT (вміст ролі не відіграє).

ДОДАТОК C — чи залежить реакція на невалідний ввід від попередньої валідної команди (до BUG-04)
Кожну невалідну команду надіслано в 8 різних попередніх станах (свіжий старт, після set speed 100,
set timeout 20, led on, set speed 100+save, set speed 100+reset, status, help).
====================================================================================================
  foo, set speed 256, set speed -1, set speed, set speed abc, set timeout 0, set timeout 61,
  set timeout, %%%, HELP, led blink, "set  speed 10"     → однакова відповідь в усіх 8 станах
  "A"×41                                                 → SYSTEM FAULT в усіх 8 станах
  set                                                    → ERROR: unknown command у 6 станах;
                                                           SYSTEM FAULT "parser state mismatch while configuration
                                                           is dirty" після set speed 100 і після set timeout 20
